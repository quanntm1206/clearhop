# Trustworthy Streaming Baseline Design

## Goal

Turn the workspace into one reproducible 16 kHz MobileDeepFilterNet pipeline
whose training target, causal behavior, streaming runtime, export, and reported
metrics agree.

## Evidence Boundary

The current notebooks, checkpoints, and plots come from several incompatible
pipeline generations. They remain historical evidence only. New claims must be
generated by the source-controlled CLI pipeline and include config, manifest
fingerprint, checkpoint metadata, and evaluation output.

## Approaches Considered

1. Harden `src/` as the source of truth. Recommended. It already contains the
   intended complex deep-filter path and has the smallest migration surface.
2. Promote the notebooks to production. Rejected because three notebooks
   duplicate divergent training logic and hide execution state.
3. Rebuild around the missing HybridDenoiser/method6 implementation. Deferred
   because its source and original checkpoint are absent.

## Architecture

The production path is a Python package plus thin CLI entry points. Shared
audio/STFT settings live in one typed configuration. Dataset code returns the
processed clean target used to construct the noisy signal. Speaker-aware split
generation creates portable relative-path manifests. Training calls one
end-to-end enhancement function. Evaluation uses the held-out test manifest.

The encoder is causal along time. Frequency convolutions may remain symmetric;
time padding is left-only. Streaming inference consumes exactly one new STFT
frame per call and carries explicit GRU, STFT, deep-filter, and synthesis state.
Offline and streaming implementations share the same feature and filtering
contracts.

## Data Contract

- Sample rate: 16000 Hz.
- Analysis frame: 320 samples. Hop: 160 samples. Frequency bins: 161.
- Dataset item: `clean`, `noisy`, and metadata. `clean` is the exact processed
  speech target used before additive noise and noisy-only corruption.
- Train mixtures vary by epoch and worker while remaining reproducible from
  `(global_seed, epoch, item_index, worker_id)`.
- Validation/test mixtures remain deterministic.
- Manifests store paths relative to the project or declared data roots.
- Split unit is speaker when speaker identity can be parsed. Unknown identities
  use a stable file-group fallback and are reported.

## Training Contract

- Input feature: unnormalized log power from the same 320/160 STFT used by
  runtime, unless fixed training-set statistics are later introduced.
- Outputs: sigmoid spectral mask plus complex causal taps.
- Reconstruction: causal complex deep filtering followed by verified synthesis.
- Loss: complex spectral loss plus SI-SDR. Every configured loss weight is
  logged. Unsupported config keys fail fast instead of being ignored.
- AMP gradient clipping unscales gradients before clipping.
- Each checkpoint records schema version, model config, audio config, data
  fingerprint, optimizer/scheduler/scaler state, epoch, step, and metrics.

## Evaluation Contract

Report noisy-input, mask-only, and mask-plus-deep-filter baselines on the same
held-out test set. Primary metrics are SI-SDR improvement and STOI. PESQ and
DNSMOS are optional only when their dependencies and model assets are present.
Report per-corpus/per-SNR slices, sample count, seed, mean, and dispersion.

No plot is accepted as evidence without its generating command and machine-
readable metric file.

## Deployment Contract

Export the neural core with explicit hidden-state input/output. Add parity tests
for eager versus TorchScript and ONNX when those runtimes are installed. The
runtime benchmark reports model size, real-time factor, per-hop latency, and
memory on the available machine. Target-device gates remain configurable until
the deployment hardware is specified.

## Error Handling

Missing datasets, stale manifests, incompatible checkpoints, unsupported
settings, and optional metric dependencies produce actionable errors. Training
never silently substitutes mock data, random checkpoints, or renamed proxy
metrics.

## Verification

- Unit tests: mixing/target alignment, deterministic validation, epoch-varying
  training, causal convolutions, identity deep filter, STFT/synthesis, config.
- Integration tests: DataLoader collation, one optimization step, checkpoint
  round trip, offline/streaming parity, export parity.
- Smoke training: a bounded run on a small speaker-disjoint subset.
- Full training: launched only after the correctness suite passes.

## Scope

This goal does not claim a target DNSMOS or mobile latency before a trustworthy
baseline and target device exist. Historical artifacts are preserved, not
rewritten.
